# Роадмап: игровой опыт

Этот файл самодостаточен. Его можно открыть в новом чате с пустым контекстом
и начать работу, ничего не спрашивая: ниже сначала устройство проекта и
правила, потом — задачи с обоснованием, планом и способом проверки.

Предыдущие роадмапы закрыты: [ROADMAP.md](ROADMAP.md) — функциональность,
[OPTIMIZATION.md](OPTIMIZATION.md) — производительность и надёжность. Здесь
речь об одном: **партия должна быть интересной на всём протяжении**, а не
только первые полсотни циклов.

---

## Часть 1. Что нужно знать перед работой

### Что это за игра

«Clots: Hem Empire» — пошаговая стратегия в кровеносной системе. Игрок
развивает цитадель, захватывает секторы, держит угрозу под контролем и
выбирает один из трёх путей доктрин. Запускается как Telegram Mini App
(`@clots_hembot`), хостинг — GitHub Pages, `https://diehlwierce.github.io/clots/`.

Объём контента: 42 сектора, 10 событий, 8 мутаций, 34 достижения, 16 глав
лора, три пути доктрин, модули и технологии по веткам.

### Стек и структура

React 19 + TypeScript (строгий: `exactOptionalPropertyTypes`,
`noUncheckedIndexedAccess`, `verbatimModuleSyntax`) + Vite 7 + Zustand 5 +
Immer. Тесты: Vitest (быстрый набор) и Playwright (E2E, Chromium, Pixel 7).

```
src/engine/          чистый движок: reduce(state, action) → { state, notices }
  content/           весь контент игры (секторы, события, модули, лор…)
  systems/           бой, лор, логистика
  sim/               боты и харнесс для измерения баланса
  save/              сериализация, миграции, санитайзинг сейва
src/store/useGame.ts мост движка и React, персистентность
src/ui/components/   вкладки и оверлеи
src/i18n/            словарь интерфейса (ru/en) + пакеты перевода контента
src/telegram/        SDK мини-приложения, темы, хаптика, облако
public/sw.js         service worker (офлайн)
```

### Правила, которые нельзя нарушать

1. **Движок не знает про React и DOM.** Всё, что относится к правилам игры,
   живёт в `src/engine` и проверяется юнит-тестами без браузера.
2. **Никакого `Math.random()` в движке и симуляции.** Случайность идёт через
   детерминированный ГПСЧ (`mulberry32`), ключ — пара `(seed, rngCursor)`.
   Партия обязана воспроизводиться по зерну; на этом стоит весь харнесс
   баланса. В политиках ботов для «броска» есть `decide(state, вероятность)`.
3. **Сейв — недоверенные данные, даже собственный.** Всё, что приходит из
   хранилища, проходит `sanitizeState` в `src/engine/save/schema.ts`.
   Новая фаза, новое поле состояния — обязательно с проверкой при загрузке.
   Список фаз там намеренно объявлен как `Record<Phase, true>`: забыть новую
   фазу не даст компилятор. Один такой пропуск уже стоил игрокам всех
   случайных событий при перезагрузке страницы.
4. **Русский — язык-образец.** `src/i18n/ru.ts` задаёт форму словаря,
   `en.ts` обязан ей соответствовать; тест это проверяет. Контент
   переводится оверлеем по id сущности, пакеты грузятся динамическим
   `import()` по языку.
5. **Размер сборки под бюджетом.** `npm run size` падает при превышении.
   Первая загрузка сейчас ~119 КБ после сжатия.

### Команды

```bash
npm run dev              # разработка
npm run verify           # типы + линтер + формат + быстрые тесты + сборка
npm run size             # бюджет размера по чанкам (нужна сборка)
npx playwright test      # E2E
npm run balance 24       # балансный отчёт: 24 забега на каждый стиль
npm run balance:mutations 4
npm run test:balance     # медленные балансные проверки
```

Проверять после правок нужно всё сразу и **без пайпов, глотающих код
возврата**. Рабочий вариант:

```bash
set -eo pipefail && npm run verify && npx playwright test
```

Локальная зелёная сборка — не гарантия: после пуша нужно убедиться, что CI
действительно зелёный (`gh run list`), а не считать это само собой
разумеющимся.

### Как измеряется баланс

`npm run balance N` прогоняет N партий каждым из пяти стилей и печатает
таблицу: доля побед, гибели, медианы циклов/секторов/уровня и «стену» —
сектор, на котором забег чаще всего обрывается. Стили описаны в
`src/engine/sim/policies.ts`:

| Стиль         | Смысл                                                     |
| ------------- | --------------------------------------------------------- |
| Агрессивная   | быстрый захват, путь Разорителя                           |
| Экономическая | вложения в добычу, путь Ткача                             |
| Осторожная    | высокие пороги лечения и низкий порог угрозы, путь Стража |
| Накопитель    | модули и технологии, доктрина только к 120-му циклу       |
| Крепость      | весь доход в дерево, захват раз в три цикла               |
| Гриндер       | доктрину не берёт вовсе, расширяется редко и наверняка    |

**Замер на 24 забегах (актуальный):**

| Стиль         | Побед | Медиана циклов | Медиана секторов |
| ------------- | ----- | -------------- | ---------------- |
| Агрессивная   | 50%   | 64.5           | 36               |
| Экономическая | 46%   | 110            | 34               |
| Осторожная    | 79%   | 183            | 37               |
| Накопитель    | 42%   | 268            | 33.5             |
| Крепость      | 58%   | 271.5          | 35.5             |
| Гриндер       | 33%   | 330            | 34               |

Отброшено измерением: буквальный стиль «не расширяться, пока дерево не
выкуплено» нежизнеспособен — доход берётся с территории, и такой бот
замирает на двух секторах. «Крепость» поэтому описана темпом захвата, а не
запретом на него.

Требование заказчика: **каждый стиль выигрывает хотя бы в 25% случаев.**
Сейчас выполняется. Порог зафиксирован тестом `tests/balance.slow.test.ts`
(с запасом — 12%, чтобы тест ловил поломку, а не фиксировал проценты).

## Часть 2. Задачи

Порядок — по влиянию на опыт. Внутри каждой задачи: в чём проблема, чем
подтверждается, что делать, как проверить.

### 1. Событийный голод во второй половине партии

**Проблема.** Событий всего десять, и повторяться они не могут:
`eventAvailable` в `src/engine/engine.ts` отсеивает всё, что уже есть в
`state.seenEvents`. При кулдауне 4 цикла и вероятности 0.3 пул выбирается
целиком очень рано.

**Измерено.** Медиана цикла последнего события: агрессивная — 73,
осторожная — 69, гриндер — 71. При медиане победного забега 187–330 циклов
это значит, что **две трети партии проходят вообще без единого события**.
Тот, кто играет накопительно, получает пустоту почти на всю партию.

**Что делать.** Не «добавить событий» — этого мало и это не решает форму
кривой. Нужно два хода:

- Разбить события на **уровни** (ранние, средние, поздние) с условиями
  открытия по циклу, уровню цитадели и числу секторов; поздние должны
  говорить о положении империи, а не о капиллярах.
- Разрешить повтор части событий, пометив их `repeatable: true`, с
  собственным кулдауном. Ставку делать на события, у которых выбор зависит
  от текущего состояния, — они не приедаются.

Довести пул до ~30 определений с явным распределением по фазам партии.
Контент — `src/engine/content/events.ts`; тексты обязательно завести и в
`src/i18n/content/en-*.ts`.

**Проверка.** Тест, который прогоняет партию и утверждает, что промежуток
без событий не превышает N циклов ни в одной трети забега. Плюс повторный
замер медианы цикла последнего события — он должен подтянуться к длине
партии.

---

### 2. Длина партии и провисание поздней игры

**Проблема.** Победа осторожной игрой — 187 циклов, накопительной — 272,
гриндом — 330. Для мини-приложения, в которое играют по 10–20 циклов за
подход, это десятки заходов. Основную часть этого времени игрок повторяет
один и тот же цикл действий: добыть, переработать, подлечить, завершить.

**Что делать.** Здесь нужен выбор направления, а не набор мелких правок.
Три варианта, взаимоисключающих не полностью:

1. **Ускорить позднюю игру.** Сделать доход и опыт растущими быстрее после
   определённого уровня, чтобы последняя треть шла заметно бодрее.
2. **Разбить кампанию на главы.** Явные рубежи с промежуточным финалом:
   регион взят — глава закрыта, показан итог, дальше следующая. Это ближе
   всего к тому, как в игру реально играют — подходами.
3. **Сжать саму карту** для основной кампании, а оставшиеся секторы
   вынести в режим «после победы» (NG+ уже есть в состоянии: `ngPlus`).

**Рекомендация:** вариант 2. Он не ломает баланс, который уже измерен, и
прямо отвечает формату мини-приложения.

**Проверка.** `npm run balance 24` — медианы циклов до промежуточных
финалов; ни один стиль не должен потерять свои 25% побед.

---

### 3. Осторожная игра доминирует

**Проблема.** 79% побед против 29% у гриндера — разрыв в 50 пунктов.
Требование «каждый выигрывает хотя бы в четверти случаев» выполняется, но
доминирующий стиль означает, что остальные — стилистический выбор, а не
равноценный.

**Важный контекст, чтобы не сделать хуже.** Эти проценты изменились не
из-за правок игры, а из-за правки ботов: правило «не лезь в сектор сильно
выше своего уровня» было описано в коде, но не применялось, и раньше
измерения частично отражали глупость ботов, а не баланс игры. Текущие числа
честнее прежних (было 50/38/63). Прежде чем крутить числа игры, стоит
убедиться, что боты не отстают от возможностей стиля.

**Что делать.** Найти, за счёт чего именно осторожная игра выигрывает
(скорее всего — лечение и низкий порог угрозы делают гибель почти
невозможной), и сделать пассивность дорогой: например, чтобы угроза росла
не только от расширения, но и от простоя, — тогда «сидеть и копить»
перестанет быть бесплатным.

**Проверка.** `npm run balance 24`, цель — разрыв между лучшим и худшим
стилем меньше 30 пунктов при сохранении минимума в 25%.

---

### 4. Стены на карте

**Измерено.** Забеги обрываются в двух местах: «Барьер гемато-энцефалии» и
«Подступы к коре». Это узкие места, а не разнообразие маршрутов.

**Что делать.** Посмотреть на связность графа секторов
(`src/engine/content/sectors.ts`): если в третий регион ведёт единственный
проход, у игры нет альтернативного плана. Добавить обход — длиннее, дороже
по логистике, но проходимый другим стилем.

**Проверка.** В отчёте `npm run balance` колонка «стена» перестаёт указывать
на один и тот же сектор для большинства стилей.

---

### 5. Обратная связь по решениям

**Проблема.** Игра сообщает, что произошло (журнал, тосты), но не помогает
понять, **почему** и **что будет дальше**. Постройка показывает эффект в
процентах, но не отвечает на вопрос «а если я вместо неё возьму другую».

**Что делать.**

- Предпросмотр итога цикла до нажатия «Завершить цикл»: доход, прирост
  угрозы, риск рейда — сейчас часть этого есть строкой под кнопкой, стоит
  довести до полноценной сводки.
- На карточке улучшения — сравнение с текущим состоянием в абсолютных
  числах, а не только процент эффекта.
- Экран итога цикла раз в N циклов: что изменилось, где растём, где
  проседаем.

**Проверка.** E2E на наличие и корректность сводки; юнит-тесты на функции
предпросмотра (они должны считать то же, что и сам цикл, — иначе предпросмотр
будет врать).

---

### 6. Разнообразие боя

**Проблема.** Приёмов четыре (удар, вскрытие, натиск, защита), выбор между
ними почти всегда очевиден: боты играют бой одной и той же лесенкой из
условий, и это работает.

**Что делать.** Дать врагам различающиеся сценарии поведения, чтобы одна и
та же лесенка не была оптимальной против всех: враг, наказывающий защиту;
враг, у которого выгодно копить импульс; враг, требующий добить быстро.
Механика намерений (`currentIntent`) уже есть — на ней это и строится.

**Проверка.** Прогнать бой ботом с фиксированной стратегией против каждого
типа врага и убедиться, что ни одна стратегия не выигрывает у всех.

---

### 7. Мутации: измерить и выровнять

**Проблема.** Мутация выбирается в самом начале и действует всю партию, но
их сила по отдельности измерялась только один раз. Разброс тогда сузили с
83 до 42 пунктов при минимуме 21% — это всё ещё двукратная разница.

**Что делать.** `npm run balance:mutations 6` даёт замер по каждой из восьми.
Выровнять до разброса менее 25 пунктов. Слабые усиливать, а не резать
сильные: мутация — это обещание стиля игры в начале партии.

---

### 8. Мелкое, но заметное

- **Звук.** Его нет совсем. Для пошаговой игры хватит нескольких коротких
  сигналов на ключевые события, с выключателем в настройках рядом с хаптикой.
- **Достижения как подсказки.** 34 награды, но они не направляют. Показывать
  прогресс ближайших — это бесплатная постановка целей.
- **Первый заход.** Обучение из 7 шагов даёт механику, но не даёт цель.
  Стоит объяснить, к чему игрок идёт, в первые же два цикла.
- **Перевод лора на английский.** Интерфейс и контент локализованы; глубина
  и качество английского лора требуют литературной вычитки.

---

### 9. Пустой эндгейм: копить больше не на что

**Проблема.** К моменту, когда карта взята, покупать нечего, а ресурсы
продолжают капать. Игра не отвечает на вопрос «чем мне теперь заниматься».

**Измерено на реальной партии игрока** (100-й цикл, сохранение разобрано):
все 38 секторов под контролем, 108 побед и ни одного поражения, всё дерево
выкуплено — и при этом на руках 16 224 плазмы, 10 315 сгустков и 3 085
эссенции, которые некуда девать. Доктрины были куплены «просто как спам
покупок», потому что больше не на что.

**Что делать.** Дать позднему доходу назначение. Варианты по возрастанию
стоимости работ:

- Бесконечные уровни у нескольких ключевых модулей с растущей ценой —
  ресурсам всегда есть куда уходить.
- Обмен ресурсов на что-то, кроме силы: ускорение цикла, снижение угрозы,
  восстановление потерянных секторов без боя.
- Ранний вход в New Game+ (`ngPlus` уже есть в состоянии) как осознанный
  выбор, а не только после победы.

**Проверка.** В отчёте `npm run balance` смотреть не только на победы, но и
на остаток ресурсов к финалу: он не должен расти неограниченно.

---

### 10. Развитие не даёт уровня

**Проблема.** Опыт начисляется за добычу, переработку, захват, победу в бою
и в рейде (`BALANCE.xp`). За покупку модуля, технологии или доктрины — не
начисляется вовсе. Игрок, вкладывающийся в дерево вместо карты, отстаёт по
уровню, а уровень даёт боевые прибавки: стиль наказывается дважды.

**Проверено экспериментом.** Временное начисление опыта за покупки
(пропорционально цене) подняло победы у большинства стилей: агрессивная
50 → 83%, экономическая 46 → 75%, гриндер 33 → 67%. Эксперимент откачен —
это не готовая правка, а замер того, насколько сильно рычаг влияет.

**Осторожно.** Рычаг мощный и поднимает всех сразу, поэтому его нельзя
включать без пересчёта остального баланса: игра станет заметно легче.

**Проверка.** `npm run balance 24` до и после; цель — сократить разрыв между
стилями, а не поднять всем проценты.

## Порядок работ

0. Пустой эндгейм (9) — игрок упирается в него, доиграв до конца, и это
   первое, о чём он сообщает.
1. Событийный голод (1) — самая большая дыра в опыте, измерена точно.
2. Обратная связь по решениям (5) — дешевле прочего и заметна сразу.
3. Длина партии (2) — требует решения по направлению, см. рекомендацию.
4. Доминирование осторожной игры (3) и стены на карте (4) — вместе, обе
   правятся замерами.
5. Бой (6) и мутации (7).
6. Мелкое (8) — по остаточному принципу, но звук стоит сделать раньше: он
   даёт непропорционально много при малой цене.

Каждый пункт — отдельный коммит с замером в сообщении: что было, что стало.
Числа в этом файле после правок обновлять, иначе следующий разговор начнётся
с устаревших данных.
